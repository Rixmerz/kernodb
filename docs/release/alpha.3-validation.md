# 1.0.0-alpha.3 validation

Release-candidate check of the tree that will become 1.0.0-alpha.3 / 1.0.0a3, done as an outside
user would: build the artifacts, install them in throwaway projects outside the repository, and run
the documented examples as written. Nothing was bumped, tagged or published.

## What was tested

| Check | How | Result |
|---|---|---|
| Python wheel | `maturin build --release`, installed with pip in a fresh venv, run with `python -I` from outside the repo | works |
| Node addon | `napi build --platform --release`, `npm pack`, installed into a fresh npm project, `.node` copied beside `index.js` | works |
| Python README | quickstart, batch ops, schemas and `find`, `find_range`, `explain`, `hybrid_search`, read the past, `verify`, `compact`, `upsert` | works |
| Node README | quickstart (as saved in `memory.mjs`), `commit` with `relate`, `upsert`, `hybridSearch`, schemas, errors | works |
| Both guides | the Python scripts, extracted from the Markdown and run unchanged | work; outputs match |
| Read-only second process | a child process opens `read_only`/`readOnly`, the writer commits, the child `refresh()`es and sees the new revision; a write on the reader and `refresh()` on the writer are refused | works |
| Retention to PRUNED | `run_retention` / `runRetention`, then `history(from_revision)`, `read_as_of` and `compare` raise `PrunedError` / `PRUNED`; `verify` stays clean | works in both |
| Bad retention rules | fractions, negatives, NaN, infinities, huge numbers, wrong types, empty rule | Python `ValueError`, Node `INVALID_ARGUMENT` |
| Typed errors | not found, bad id, locked, payload too large, has relations, schema, closed handle, upsert on a non-unique field | all typed |
| Rust examples | `cargo run --release -p kernodb --example agent_memory`, `chat_history`, `document_store` | run |
| Doctests | `cargo test --release -p kernodb --doc` | 7 passed |
| Publish dry run | `cargo publish --dry-run -p kernodb-core -p kernodb-storage -p kernodb-units -p kernodb` | passes |
| Versions | see below | consistent at alpha.2, ready to bump |

The one-crate-at-a-time form, `cargo publish --dry-run -p kernodb-storage`, fails for as long as the
version is not bumped: it verifies against the alpha.2 already on crates.io, which lacks the new
`Refresh` trait. The four crates in one command verify against each other and pass. After the bump
and the real publishes, in order, each crate finds its predecessor.

## Found and fixed

1. **Node numeric options truncated or wrapped** (bug). `history({ limit: 1.5 })` returned one
   revision, `limit: -1` meant 4294967295, `readAsOf(id, 1.5)` read as of 1, and the same held for
   `schemaVersion`, `maxBatchOps`, the `restore` revision, a `relate` end given as an index, and the
   `hybridSearch` numbers. They are now validated with the helper the retention rules already used
   (`whole`, `whole_u32` in `bindings/node/src/lib.rs`) and throw `INVALID_ARGUMENT`.
   Regression test: `a numeric option that is a fraction, a negative or NaN is refused, never
   truncated or wrapped` in `bindings/node/__test__/index.test.mts`. It fails against the addon built
   before the fix (checked with `NAPI_RS_NATIVE_LIBRARY_PATH`) and passes after.
2. **Python README and Node README said retention is not configurable** (doc mismatch). Both
   describe `run_retention` / `runRetention` elsewhere. Rewritten. The Node error table now lists
   `history` as a source of `PRUNED`.
3. **`docs/guides/one-unit-per-entity.md` said there is no upsert** (doc mismatch), while the tree has
   `upsert` in the facade and both bindings. The guide now uses it. README.md's table row follows.
4. **`docs/bindings-coverage.md` did not list `upsert`** (doc mismatch). Added, for the call and the
   batch op.
   Regression test for 2 to 4: `test_the_guide_scripts_run_as_written` in
   `bindings/python/tests/test_kerno.py` runs both guide scripts and checks their output. It fails
   against the old one-unit guide.

## Versions, ready to become 1.0.0-alpha.3 / 1.0.0a3

All of these still say alpha.2 and are all that has to change at the bump:

- `Cargo.toml`: `workspace.package.version` and the four `version =` of the internal dependencies.
- `bindings/python/Cargo.toml` (the wheel version comes from it: `1.0.0a2` today) and its dependency
  on `kernodb`; `bindings/node/Cargo.toml` likewise.
- `bindings/node/package.json`, and `index.js`, whose version checks are regenerated by `napi build`.
- The three lock files (`Cargo.lock`, `bindings/python/Cargo.lock`, `bindings/node/Cargo.lock`).
- The alpha banners and "what is new" in `README.md`, `bindings/python/README.md`,
  `bindings/node/README.md`, and the install line in `README.md`.
- `CHANGELOG.md`: rename `[Unreleased]` to `[1.0.0-alpha.3] - <date>`. A checklist
  `docs/release/1.0.0-alpha.3-checklist.md` does not exist yet (alpha.1 and alpha.2 have one).

## Not done, or not checked

- **Python negative numbers**: `db.history(id, limit=-1)` and similar raise `OverflowError`, not
  `ValueError`. It is Python's own behaviour for a negative given to an unsigned parameter, and the
  retention options (the documented case) already raise `ValueError`. Left as is.
- Only Linux x86_64, CPython 3.14 and Node 26 were exercised; macOS, Windows, musl and aarch64 wheels
  were not built.
- The Node guides are Python examples; their Node equivalents were run by hand, not from the Markdown.
- The full `cargo test --workspace --release` result is in the report that came with this change.
