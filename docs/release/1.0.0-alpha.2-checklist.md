# Release checklist: 1.0.0-alpha.2 (Python 1.0.0a2)

Status: **ready on branch `ccr-5d0e38e9-1hmqh0` (Rixmerz/kernodb#1).** Development, tests and
measurements were done in the cloud session. Merging, bumping the version, tagging and
publishing are the owner's steps, on their own machine (below).

## What this release carries

See `[Unreleased]` in `CHANGELOG.md` for the full list. In short:

**Breaking (ADR-0023, the format cut):**
- A database written by 1.0.0-alpha.1 is refused (`LayerTooOld`). Move one across with
  `kerno <dir> export` (alpha.1) and `kerno import` (alpha.2). Every database is created at
  units layer 7.
- The keyword (BM25) index is **opt-in per type**: `Db::set_fulltext(type, true)`, Python
  `db.set_fulltext(type, True)`, `kerno-server --fulltext <types>`. Switching a type that has
  units reindexes or clears them in the same commit.
- New SSTs carry the `incompat` bit `BLOCK_LZ4` (LZ4 data blocks, v1.md §4.4). Engine format
  stays v1 (feature bit, ADR-0013 amendment). alpha.1 refuses those tables (HDR-6).

**Performance (measured, `docs/testing/python-vs-sqlite.md`):**
- Keyword index opt-in: writes 4–6x faster and the store 3.5x smaller for types not indexed.
- LZ4 blocks: a real store 66 → 35 MB; a small revision 481 → 133 B on disk.
- Relations: counts written once per change set, active-unit cache (82 → 63 ms on 9,000
  relations among 300 units).
- Against SQLite with the same durability: one write per commit about the same; batches about
  3x; relations 6–11x; reads within 1.5x; disk about 2x smaller in the benchmark.

**API (facade and Python, from the LiveSpec integration, issue #2):**
- Relations inside a batch (`relate`, `relate_unique`, ends that are units of the same batch),
  `delete_cascade`, `update_if_changed`, `archive`, `unarchive`, `restore`, provenance
  (`reason`, `actor`, `source`), `last_commit_seq`, clamped `read_as_of`, `relations(type)`,
  `compact`, `open_with_limits` / `max_batch_ops`.
- Python: everything above, plus schemas, indexes, documents, `find`, `execute`,
  `open(read_only=)`, and typed exceptions under `KernoError`.

**Bindings (owner's commits 0cd3bf1, e035035):** Python gains `hybrid_search`, `explain`,
`find_range`, history bounds and order, `compare`, `oldest_revision` and `query(lifecycle=)`;
Node reaches parity with Python. Both have `fulltext(type)`. The server has `GET`/`PUT
/v1/types/{type}/fulltext`, the clients have `set_fulltext` / `setFulltext`, and the Vercel AI
memory turns its type's index on by itself.

**Fixes:** issue #3 (Python client tests on Windows), #4 (server test harness on Windows, and a
real bug: `file:///C:/dir` backup URLs), #5 (frozen corpora kept LF on checkout). The
`Db::verify` documentation was corrected.

**Docs:** the Python README (the PyPI page) was rewritten, PyPI metadata links were added,
`wheels.yml` builds musllinux wheels, and ADR-0022 / ADR-0023 / units-v7 / v1.md §4.4 were added.

## Steps for the owner (on your machine)

1. **Review and merge** Rixmerz/kernodb#1 into `main`. The commits say `fixes #3`, `fixes #4`
   and `fixes #5`, so those issues close on merge.
2. **Run CI on the merge commit**, including the jobs not run above: trigger the weekly
   workflow by hand, and `wheels.yml` / `npm.yml` with `workflow_dispatch`. Check the two new
   musllinux targets.
3. **Bump the version:** `scripts/bump-version.sh 1.0.0-alpha.1 1.0.0-alpha.2`, then
   `git grep -n 1.0.0-alpha.1` (only CHANGELOG history should remain).
4. **Changelog:** promote `[Unreleased]` to `[1.0.0-alpha.2] - YYYY-MM-DD`. Re-run
   `maturin build --release && maturin sdist && twine check dist/*` in `bindings/python`.
5. **Commit, tag and push:** `git tag -a v1.0.0-alpha.2 -m "1.0.0-alpha.2"`, then
   `git push origin main v1.0.0-alpha.2`. Approve the `pypi` (and npm) environments when the
   workflows ask.
6. **crates.io**, in dependency order: `kernodb-core`, `kernodb-storage`, `kernodb-units`,
   `kernodb` (`cargo publish -p <crate>`; each needs the one before it on the index).
7. **Check the published packages:** in a fresh venv, `pip install --pre kernodb==1.0.0a2`
   and run the README quickstart. Check that the PyPI page shows the new README and links.
8. **LiveSpec:** in its `ccr-5d0e38e9-1hmqh0` branch, change the `kerno` extra to
   `kernodb>=1.0.0a2` and run `uv lock` (it needs the package on PyPI).

## Open decisions (not blocking alpha.2)

- **Engine performance work** still listed in `docs/testing/python-vs-sqlite.md`: allocation
  and the memtable dominate the profile of batch writes.
- **Several processes on one directory.** A read-only open still takes the exclusive lock.
- **BM25 / hybrid search in Python.** Not exposed yet; now that the index is opt-in, it can
  be exposed as a per-type feature. Stage 8 criterion Q4 is still not met.
- **Renaming a file in LiveSpec** starts a new history for its symbols (by design in the
  experiment).
