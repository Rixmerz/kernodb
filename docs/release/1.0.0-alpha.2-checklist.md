# Release checklist: 1.0.0-alpha.2 (Python 1.0.0a2)

Status: **prepared on branch `ccr-5d0e38e9-1hmqh0`. Nothing is merged, bumped, tagged or
published.** The owner does those steps on their own machine.

## What this release carries

Everything under `[Unreleased]` in `CHANGELOG.md`. In short:

- The `kerno` facade adds batch relations (`Batch::relate` / `relate_unique`, with ends that
  can be units stored earlier in the same batch), `delete_cascade`, `update_if_changed`,
  archive / unarchive / restore in a batch, `Db::commit_with` (provenance and a `Committed`
  report), `Db::last_commit_seq`, a clamped `Db::read_as_of`, `Db::compact`,
  `Db::relations`, and `UnitError::is_corruption`.
- The Python bindings expose all of the above, plus schemas, indexes, documents, `find`,
  `execute`, `open(read_only=)`, and typed exceptions under `KernoError`.
- `Db::verify` documentation is corrected (storage corruption is an `Err`). Python's `verify()`
  reports it as `storage_error`.
- The Python README is rewritten (it is the PyPI page). It covers install from PyPI, concepts,
  common tasks, API, errors, performance, durability, concurrency and limits.
- PyPI metadata adds Homepage, Documentation, Changelog and Issues links, plus OS
  classifiers.
- `wheels.yml` adds musllinux x86_64 and aarch64 wheels, tested in Alpine.
- The comparison against SQLite and its profile are in `docs/testing/python-vs-sqlite.md`.

## Steps for the owner (on your machine)

1. Review and merge the branch: Rixmerz/kernodb#1.
2. Run the full CI locally or on the merge commit: `cargo test --workspace --exclude kernodb-storage --all-features --release` and `cargo test -p kernodb-storage --all-features --release`.
3. Run `wheels.yml` with `workflow_dispatch` on `main`. Check that every target, including the
   two new musllinux ones, builds and passes its tests.
4. Bump versions to `1.0.0-alpha.2` (crates, `bindings/python` via `Cargo.toml`, `bindings/node`).
5. Promote `[Unreleased]` in `CHANGELOG.md` to `[1.0.0-alpha.2] - YYYY-MM-DD`.
6. Tag `v1.0.0-alpha.2` and push the tag. Approve the `pypi` environment when the workflow asks.
7. Check the PyPI page renders the new README and links, then run
   `pip install --pre kernodb==1.0.0a2` in a fresh venv and the README quickstart.
8. Publish the crates in the order of the alpha.1 checklist if the Rust API changes should
   reach crates.io too (`kernodb` changed; `kernodb-units` gained `is_corruption`).

## Open decisions for the owner (not done)

- **A per-type opt-out of full-text indexing.** Today every UTF-8 payload is indexed. That
  makes writes about 7x slower and the store about 3.5x larger for data nobody searches.
  The opt-out has to be persisted, so it touches the format frozen by ADR-0013. See
  `docs/testing/python-vs-sqlite.md`.
- **Engine performance work** listed in that document: adjacency counts on relation writes,
  allocation, head reads inside a change set, and space per revision.
- **Several processes on one directory.** A read-only open still takes the exclusive lock.
- **BM25 / hybrid search in Python.** Not exposed; Stage 8 criterion Q4 is still not met.
