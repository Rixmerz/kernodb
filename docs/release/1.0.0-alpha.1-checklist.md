## Publish order and commands

Run from the repository root, from a clean `main` after the merge. Tokens are never written in files: use your secrets tool (for example `hide exec CRATESTOKEN -- <command>`).

1. **Tag and verify**
   ```bash
   git status --short   # must be empty
   cargo fmt --all --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features --release
   ```

2. **crates.io**, one crate at a time; wait until each one appears in the index before the next:
   ```bash
   cargo publish -p kerno-core
   cargo publish -p kerno-storage
   cargo publish -p kerno-units
   cargo publish -p kerno
   ```
   Before each real publish, run the same command with `--dry-run` once more.

3. **npm** (pre-release, so use the `alpha` tag; it keeps `latest` untouched):
   ```bash
   # kernodb: published by CI on a `v1.0.0-alpha.1` tag (.github/workflows/npm.yml), which also publishes the platform packages.
   (cd clients/typescript && npm ci && npm run build && npm publish --access public --tag alpha)
   (cd integrations/vercel-ai && npm ci && npm run build && npm publish --access public --tag alpha)
   ```
   Check that `npm.yml` publishes `kernodb` with the `alpha` tag; if it does not, fix the workflow before tagging.

4. **TestPyPI**, then install from it in a clean environment and smoke-test:
   ```bash
   python -m build bindings/python   # wheels for all platforms: use the artifacts of wheels.yml
   twine upload --repository testpypi dist/*
   python -m build clients/python && twine upload --repository testpypi clients/python/dist/*
   python -m build integrations/langchain && twine upload --repository testpypi integrations/langchain/dist/*
   python -m build integrations/llamaindex && twine upload --repository testpypi integrations/llamaindex/dist/*
   ```
   Upload order matters for installs: `kernodb`, `kerno-client`, then `kerno-langchain` and `kerno-llamaindex`.

5. **PyPI**, same order and files as TestPyPI, only after the TestPyPI install works:
   ```bash
   twine upload dist/*   # repeat per package directory, in the order above
   ```

6. **Tag and release notes**: push the tag `v1.0.0-alpha.1` and copy the `[1.0.0-alpha.1]` section of `CHANGELOG.md` into the GitHub release, marked as a pre-release.
