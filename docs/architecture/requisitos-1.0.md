## 1. Estados

- **Cumplido**: lo que pide el requisito está en el repositorio, y un fichero o una prueba lo muestra.
- **Cumplido con límites declarados**: se cumple en el alcance que el documento de origen declara. El límite está escrito en ese documento y aquí se cita.
- **No cumplido**: falta algo que el repositorio no tiene. Ninguno de los siete está en este estado.

Seis requisitos están en «Cumplido con límites declarados». Uno, el 7, está en «Cumplido»: el threat model declara sus límites, y varias amenazas siguen abiertas, como dice el propio requisito.

## 3. Lo que 1.0 necesita y no es ingeniería

Estos puntos no están en D13, pero 1.0 no se puede declarar sin ellos:

- **Uso real fuera del equipo (D12; ADR-0019).** No hay ninguno. El único caso de uso es `examples/agent-memory/`, que el acta llama caso de uso interno (acta §2.4 y D12). ADR-0019 condiciona el cobro a «un 1.0 con formato estable, migraciones y usuarios reales en producción». Falta que alguien ajeno al equipo use la API y quede registrado.
- **La declaración del propietario (D12).** 1.0 se declara solo después de D13 y del uso real. Congelar el formato de exportación y prometer semver de la API son promesas a usuarios; el acta no las deja a este documento, y no se hacen aquí.
- **Fuera de D13, pero pendiente para aceptar cualquier contribución externa**: la aprobación del texto del CLA por el propietario (D15). Hay un borrador sin vigor en [`docs/legal/cla-propuesta.md`](../legal/cla-propuesta.md).

**1.0 no está declarado.** Ningún documento del repositorio lo declara, y este tampoco.
