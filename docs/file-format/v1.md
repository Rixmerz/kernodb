## 0. Scope and notation

This document specifies **byte by byte** the three file types of the engine (`MANIFEST`, `NNNNNN.wal`, `NNNNNN.sst`), the validation rules that any reader applies, the recovery rules that are part of the format, and the invariants that any writer must respect. What is not here (compaction policy, target sizes, threads) is not part of the format and may change without migration.

- Each rule has an identifier (`HDR-n`, `VAR-n`, `WAL-n`, `SST-n`, `MAN-n`, `REC-n`, `W-n`, `SEM-n`, `VEC-n`). The error messages and the `Issue`s of `verify()` cite the identifier; they never include key or value bytes (threat T-08).
- Result classes: **`Corruption`** (damage or a crafted file), **`Incompatible`** (unknown or unsupported version or feature; it is not damage), **`InvalidArgument`** (the directory is not a Kerno database, or does not exist), **read-only** (the database is opened but rejects writes with `ReadOnly`).
- "Orphan" means a canonical file that the recovered state does not need: it is deleted in read-write and only reported in read-only mode and by `verify()`.

## 1. Conventions

### 1.1 Integers, varints and strings

- All fixed-width integers are **little-endian**.
- **VAR-1.** `varint` is unsigned LEB128 of at most 10 bytes; the tenth byte must be `0x00` or `0x01`. A varint cut off by the end of the structure that contains it breaks the rule of that structure, like any truncated field (§13.1).
- **VAR-2.** The encoding must be **minimal**: a final `0x00` byte preceded by a byte with the continuation bit is `Corruption` (the value 0 is encoded as a single `0x00`). Thus decoding and re-encoding reproduce the same bytes.
- **VAR-3.** `bytes(x)` is `varint(len) ‖ x`; `len` is validated against the limit of the context (§1.4) and against the bytes remaining **before** any memory is reserved. The same holds for every length read from disk (the `len` of a TLV, `key_len` and `value_len` of an entry of a data block): if it exceeds the limit of the context or the bytes remaining in the structure that contains it, the rule is VAR-3.

### 1.2 Checksums

- Algorithm: **CRC-32C** (Castagnoli, reflected polynomial `0x82F63B78`, initial value `0xFFFFFFFF`, final xor `0xFFFFFFFF`, no mask), that of the `crc32c` crate. Check value: `crc32c("123456789") = 0xE3069283`.
- **CRC with context.** `crc(ctx; data)` = `crc32c(ctx ‖ data)`, where `ctx` is not stored: the reader supplies it. Thus a block copied from another file or another offset does not verify.

| Structure | `ctx` |
|---|---|
| Common header | none (it already includes `file_number` and `db_id`) |
| WAL frame | `file_number u64` (the number in the file name) |
| SST block | `file_number u64 ‖ block_offset u64` (offset of the first byte of the block) |
| SST footer | `file_number u64` |
| MANIFEST record | `generation u64` (the `file_number` of the MANIFEST header) |

### 1.3 TLV

`TLV = tag varint ‖ len varint ‖ value[len]`. The rules of order, repetition and unknown tags depend on the structure (§7.6, §8.3). A `value` of type `varint` must occupy exactly `len` bytes; one of type `u8` has `len = 1`. A `value` that does not meet this (a varint cut by `len` or followed by more bytes, a `u8` with `len ≠ 1`) breaks the rule of the structure; VAR-1 and VAR-2 inside the value are reported as such.

### 1.4 Limits

The **format limits** are enforced by any reader (`Corruption` if they are exceeded). The **API limits** of Phase 1 are stricter and are enforced by the writer with `InvalidArgument` before writing anything; raising an API limit within the format limit is not a format change.

| Element | Format limit | API limit (Phase 1) |
|---|---|---|
| User key, ends of a range | 16 KiB | 512 B (`MAX_KEY_LEN`) |
| Value | 64 MiB | 1 MiB (`MAX_VALUE_LEN`) |
| Operations per commit | 2^24 | 2^20 (`Limits::max_batch_ops`) |
| Bytes encoded per commit | WAL frame payload ≤ 2^30 | 64 MiB (`Limits::max_batch_bytes`) |
| Commits per WAL frame | 1..=65 536 | group ≤ 1 024 (`GroupCommitConfig`) |
| Payload of a WAL frame | 1..=2^30 bytes | — |
| Payload of an SST data block | ≤ 80 MiB | target 4 KiB |
| Payload of an SST meta block, of a MANIFEST record | ≤ 256 MiB | — |
| `header_len` | 96..=4096, multiple of 8 | 96 |
| File number | 1..=2^48−1 | — |
| Commit sequence | 1..=2^63−1 (0 = empty database) | exhausted ⇒ `InvalidArgument` |
| `edit_seq` of a MANIFEST record | 1..=2^63−1 | — |
| Levels (`num_levels`) | v1 accepts exactly 7 | 7 |
| Files per level | ≤ 2^20 | — |
| Bloom filter: `k`, `nbits` | `k` 1..=30; `nbits` ≥ 64, multiple of 8, ≤ 2^32−8 | `k` = 7, 10 bits per key |

## 2. Directory

| Name | Header | Rules |
|---|---|---|
| `LOCK` | none (exempt: it holds no state) | 0 bytes; never deleted; taken (exclusive) before any mutation. It is the only file that a read-only opening, `verify()` or `inspect()` may create. |
| `MANIFEST` | `KRNO_MAN` | Fixed name. There is no `CURRENT` file: each *checkpoint* replaces `MANIFEST` by atomic rename (§8.9). |
| `MANIFEST.tmp` | `KRNO_MAN` | Exists only during a checkpoint. An old one is ignored in read-only mode and deleted in read-write. |
| `NNNNNN.wal` | `KRNO_WAL` | Commit journal (§6). |
| `WAL.spare` | — | Spare WAL: zeros, no format header (§6.5). The writer creates it and only renames it to `NNNNNN.wal` when it is complete and durable; one left after a crash may be half-written and is not used. It is ignored in read-only mode and deleted in read-write, on opening and on closing. |
| `NNNNNN.sst` | `KRNO_SST` | Immutable sorted table (§7). |
| `CURRENT`, `OPTIONS`, `IDENTITY` | — | **Reserved** names; v1 does not write them. If they appear, they are treated as unknown. |
| Any other | — | Unknown: ignored and never deleted; `verify()` reports it. |

- **DIR-1.** A name is canonical if it is `{n:06}.wal` or `{n:06}.sst` with `format!("{n:06}") == stem` and `1 ≤ n ≤ 2^48−1`. `1.wal`, `0000001.wal` or a number greater than 2^48−1 are "unknown". The WAL and SST numbers come from a single counter (`next_file`) and are never reused.
- **DIR-2 (creation).** A database is only created if the directory does not exist or contains only `LOCK`, `MANIFEST.tmp` and/or `WAL.spare`. A directory with any other file and without `MANIFEST` is not touched: `InvalidArgument("not a Kerno database")` (this covers `data.kbt` of the B+ tree prototype and `log` of the reference engine).
- **DIR-3 (creation protocol).**
  1. If the directory does not exist: `create_dir_all` and `sync_dir(parent)`. It is the only case in which the parent is synced.
  2. `lock(LOCK)`.
  3. Write `MANIFEST.tmp` (header with `generation` 1 and `first_edit_seq` 1) with a single record `SNAPSHOT{edit_seq 1, CLEAN, last_seq 0, next_file 1, log_number 1, prev_generation 0, no files}` → `sync_data` → `rename` to `MANIFEST` → `sync_dir`.
  4. Normal session start (§9.4).

  A crash during creation leaves at most `LOCK` and `MANIFEST.tmp`, which DIR-2 treats again as "create".

## 3. Common header (96 bytes, offset 0)

Every `MANIFEST`, WAL and SST starts with this header; so do the append-only files (ADR-0003 §1 allows the header at the end, but a log cannot end in a header while it is being written).

| Offset | Size | Field | v1 |
|---|---|---|---|
| 0 | 8 | `magic` | `KRNO_MAN`, `KRNO_WAL` or `KRNO_SST` (`KRNO_EXP` reserved for the logical export of Phase 4) |
| 8 | 4 | `format_version` u32 | 1 |
| 12 | 4 | `header_len` u32 | 96 |
| 16 | 8 | `compat` u64 | §4 |
| 24 | 8 | `ro_compat` u64 | §4 |
| 32 | 8 | `incompat` u64 | §4 |
| 40 | 16 | `db_id` | random at database creation (injectable in tests); the same in all the files of the database |
| 56 | 8 | `file_number` u64 | WAL and SST: the number in the name. MANIFEST: `generation` (≥ 1, +1 per checkpoint) |
| 64 | 24 | per-type fields | see below |
| 88 | 4 | `reserved` u32 | 0 |
| 92 | 4 | `header_crc` u32 | `crc32c(bytes[0 .. header_len−4])` |

Per-type fields (bytes 64..88; every byte not listed is 0):

| Type | Fields |
|---|---|
| MANIFEST | `first_edit_seq u64 @64`: `edit_seq` of record 0 of this file |
| WAL | `base_seq u64 @64`: sequence that the first commit of the file must carry (= previous last sequence + 1) |
| SST | `block_size u32 @64`: target size of the data block, informative (512..=1 MiB; v1 writes 4096) |

**Permanent rule (all future versions):** `magic` @0, `format_version` @8 and `header_len` @12 do not move, and the header CRC always occupies the last 4 bytes of `header_len`. A future version may lengthen the header; a v1 reader validates it with its CRC and rejects it by version (HDR-4) before interpreting anything else.

**Validation order** (identical for the three types; it runs before any write):

- **HDR-1.** A file of less than 96 bytes: `Corruption`, except the WAL files without frames that REC-7 and REC-10c allow (a newly created WAL whose header was not yet durable).
- **HDR-2.** `magic`: that of the expected type ⇒ continue. A *magic* of the M0 prototype (`KRNOMAN1`, `KRNOSST1`, `KRNOLOGC`) ⇒ `Incompatible("M0 prototype format")`. Any other ⇒ `Corruption`.
- **HDR-3.** `header_len` outside 96..=4096, not a multiple of 8, greater than the file, or wrong CRC ⇒ `Corruption`. The CRC is checked **before** the version, so that random damage is never presented as `Incompatible`.
- **HDR-4.** `format_version` = 0 ⇒ `Corruption`; > 1 ⇒ `Incompatible`.
- **HDR-5.** `header_len` ≠ 96 with `format_version` = 1 ⇒ `Corruption`.
- **HDR-6.** `incompat` with any unknown bit, or with `AEAD` ⇒ `Incompatible`.
- **HDR-7.** `ro_compat` with any unknown bit ⇒ the whole database is opened read-only.
- **HDR-8.** Unknown `compat` bits ⇒ ignored; a rewritten file (checkpoint, compaction) does not keep them (a writer only sets bits that it implements).
- **HDR-9.** `reserved` @88 or the unused per-type bytes ≠ 0, or `block_size` of an SST outside 512..=1 MiB ⇒ `Corruption`.
- **HDR-10.** WAL and SST: `db_id` ≠ that of the `MANIFEST`, or `file_number` ≠ the number in the name ⇒ `Corruption("file belongs to another database or was renamed")`.

## 4. Feature bits

### 4.1 v1 register

| Word | Bit | Name | State in v1 |
|---|---|---|---|
| `incompat` | 0 | `AEAD`: sealed blocks, records and frames; the slots of §5 are in use | Defined and **not supported** in Phase 1 ⇒ `Incompatible("encryption not supported")` |
| `incompat` | 1..62 | reserved (planned: block compression, WAL recycling, separated values, multi-version SST, migration state) | unknown ⇒ `Incompatible` |
| `incompat` | 63 | `DRAFT`: file written by the draft before the freeze; **retired**, no longer written and rejected | see §4.3 |
| `ro_compat` | 0..63 | reserved | unknown ⇒ read-only |
| `compat` | 0..63 | reserved | unknown ⇒ ignored |

### 4.2 Rules

- Bits are evaluated **per file**, over every file that the opening reads: the `MANIFEST`, all the referenced SSTs and all the live WALs (§9). Orphans are not validated.
- Any new structure that a v1 reader would not understand arrives with a bit, in the corresponding word; ADR-0013 records it.
- `Incompatible` and read-only are decided **before any mutation**: the directory remains identical byte for byte (except the creation of `LOCK`).

### 4.3 `DRAFT` bit

- Until the freeze, every writer set `incompat` bit 63 in all the files, and the readers of the draft accepted it.
- Frozen on 2026-10-31: the writers stop setting it, the bit leaves the known set, all the vectors were regenerated, and the negative vector `draft-v1` was added (§13.2). The reader checks bit 63 by its name in HDR-6, before the unknown bits: a database created with the draft is rejected with `Incompatible("pre-freeze draft format")` instead of being read with rules that may have changed.

## 5. AEAD slot

- `slot[40] = nonce[24] ‖ tag[16]` (24 bytes cover XChaCha20-Poly1305; a 12-byte nonce, as in AES-256-GCM-SIV, occupies the first 12 and leaves the rest at zero).
- It is **always** present, just before the CRC, in every SST block and in every MANIFEST record. In WAL frames it is present **only if** the header of that WAL has `AEAD` (a WAL never survives a clean close, so enabling encryption does not require migrating it, and small commits do not pay 40 bytes; decision pending signature in ADR-0013, with the alternative "slot always present" described in a single constant, `FRAME_SLOT_ALWAYS`).
- **AEAD-1.** With `AEAD` disabled, the slot must be zero, or it is `Corruption`. The CRC covers it, so a random bit flip is detected by the CRC, and a file crafted with a valid CRC is detected by this rule. No byte remains uncovered.
- The associated data (file number, offset, block type) is specified with ADR-0006; this reservation does not block that decision.

## 6. WAL (`NNNNNN.wal`)

### 6.1 Layout

```text
[0, 96)        cabecera común (KRNO_WAL, file_number, base_seq)
[96, ...)      trama*   (cada trama = un grupo de commits con un único CRC)
[..., EOF)     opcional: relleno de ceros (permite preasignar sin cambiar el formato)
```

### 6.2 Frame

| Offset | Size | Field | Rules |
|---|---|---|---|
| 0 | 4 | `payload_len` u32 | 1..=2^30 |
| 4 | 4 | `crc` u32 | `crc(file_number; bytes[0..4] ‖ bytes[8..32] ‖ payload ‖ slot?)` |
| 8 | 8 | `first_seq` u64 | first frame of the file: `base_seq`; afterwards: `first_seq` + `count` of the previous frame |
| 16 | 8 | `synced_len` u64 | bytes of **this file** that the writer knew to be durable when it wrote the frame; `0` (or the header) or `96 ≤ synced_len ≤ offset of the frame` |
| 24 | 4 | `count` u32 | commits of the frame, 1..=65 536; `first_seq + count − 1 ≤ 2^63−1` |
| 28 | 4 | `reserved` u32 | 0 |
| 32 | `payload_len` | `payload` | `count` commits (§6.3), consumed exactly |
| … | 40 | `slot` | only if the header has `AEAD` |

Commit `i` (from 0) of the frame has the sequence `first_seq + i`.

### 6.3 Commit and canonical form

```text
commit := op_count varint (0..=2^24) ‖ op*
op     := 0x01 bytes(key) bytes(value)     PUT
        | 0x02 bytes(key)                  DELETE
        | 0x03 bytes(start) bytes(end)     DELETE_RANGE  [start, end), start < end
```

- **WAL-C1 (canonicalization).** The writer processes the `WriteBatch` in order: `Put`/`Delete(k)` replaces the previous point operation on `k`; `DeleteRange(a, b)` with `a < b` removes the previous point operations with a key in `[a, b)` and adds the range; `DeleteRange(a, a)` has no effect. The result is written as **all the ranges**, sorted by `(start, end)` strictly increasing and without duplicates, **followed by** the point operations with keys strictly increasing.
- **WAL-C2.** Applying first the ranges and then the points, all with the same sequence, gives the same state as applying the batch operation by operation (SEM-3).
- **WAL-C3.** A non-empty batch whose operations all cancel out (e.g. only `delete_range(a, a)`) is a commit with `op_count = 0`: it consumes a sequence and does not change the state. An empty batch is not a commit.
- **WAL-C4.** The reader checks the canonical form (order, uniqueness, `start < end`, the limits of §1.4); any deviation in a frame with a valid CRC is `Corruption`.

### 6.4 WAL replay (reader)

Let `expected` be the sequence expected for the first commit (for the oldest WAL, the `last_seq` of the MANIFEST + 1; for the following ones, the one after the last replayed).

- **WAL-R1.** If the header is valid and `base_seq ≠ expected` ⇒ `Corruption`.
- **WAL-R2.** The frames are read in sequence, as a stream (read blocks of 1 MiB; the file is not loaded whole; a frame larger than that is read whole). Reading stops at the first frame, at offset `P`, that is incomplete (fewer than 32 bytes remain or the frame does not fit in the file), has `payload_len` outside 1..=2^30, or fails the CRC.
- **WAL-R3.** A frame with a valid CRC but `first_seq ≠ expected`, `count` or `synced_len` out of range, `reserved ≠ 0`, a non-zero slot or a malformed payload (WAL-C4) ⇒ `Corruption`.
- **WAL-R4 (clean end).** If from `P` to the end all bytes are zero, the WAL ends cleanly at `P` (padding).
- **WAL-R5 (broken tail versus damage).** Otherwise, from `P+1` to the end, candidate frames are searched at each offset `q` with: `payload_len` in range, the frame fits in the file, `first_seq ∈ [expected, expected + (q − P)]`, `P < synced_len ≤ q`, and a valid CRC. If any exists ⇒ `Corruption` (the bytes at `P` were durable when that frame was written, so the damage is later). If none ⇒ **broken tail** at `P`. The bound on `first_seq` holds for group frames with any number of commits: each lost frame in `[P, q)` has 32 bytes of header and each of its commits takes at least one byte of payload (an empty commit, WAL-C3, is `op_count = 0`), so before `q` there are fewer than `q − P` commits.
- **WAL-R6 (broken header).** If the header does not validate under HDR-1, HDR-3 or HDR-2 with an unknown *magic* (neither v1 nor M0's; a header whose creation was cut by a crash may be zeros or carry foreign bytes, but never the *magic* of another file type), `P = 0` is taken and the WAL-R5 search is applied (`first_seq ∈ [expected, expected + q]`) with `ctx = file_number` from the name and frames without slot (with slot if `FRAME_SLOT_ALWAYS`), **without the condition on `synced_len`**: a valid frame (correct CRC) under a broken header ⇒ `Corruption`, whatever its `synced_len`. The writer syncs the header (W-1) before accepting the first frame, so no frame can precede a durable header: a broken header with a frame behind it is media damage, not a cut creation. If there is no frame, the WAL is considered **without frames** with a broken header (the crash arrived before the header was durable, and no frame had been accepted).
- **WAL-R7.** Which WALs may end in a broken tail or have a broken header is decided by REC-10.

### 6.5 WAL writer rules

- **W-1 (creation).** `CreateNew`, write the header, `sync_data` of the header and `sync_dir`. No frame is written before the header and the directory entry are durable (one more `sync_data` per rotation, once every `write_buffer_bytes`).
- **W-2 (rotation in `Buffered`).** Before creating the next WAL, `sync_data` of the current WAL (so only the most recent WAL can be broken).
- **W-11 (`synced_len`).** The writer keeps `synced_len`: 96 (the header, synced in W-1) when the file is created; after each successful `sync_data`, `synced_len := bytes written`. Each frame carries the current value when it is written. A failed `fsync` poisons the handle and no further frame is written to that file (W-7).

Consequences (they must hold and are tested):

| Mode | `synced_len` of each frame | Effect on WAL-R5 |
|---|---|---|
| `Sync`, one writer | from the second frame, its own offset | identical to M0: damage in a frame followed by another valid one ⇒ `Corruption` |
| Group commit | the prefix synced before writing the group | one frame = one group, one CRC: there are never "holes" inside a group |
| `Buffered` | the prefix synced at the last rotation or `sync()` | a broken tail after a power cut is accepted (prefix, I-03); after a later `sync()`, it is not |
| Broken header | every frame carries `synced_len ≥ 96` | with a valid frame behind it ⇒ `Corruption` (WAL-R6); without frames, the newly created and broken WAL counts as empty |

**Preallocation and recycling (no new rule).** The writer may leave the WAL as `header ‖ zeros` of a given size, already written and synced, before the first frame, so that the `fsync` of a frame overwrites blocks already allocated and does not confirm a change of size. It is the padding of §6.1 and WAL-R4: the reader stops at the first invalid frame and accepts the rest only if it is zeros, so no byte of a valid file changes, and the `incompat` bit reserved for WAL recycling (§4) is not used. A file that is reused for another WAL (another number, another header) **must** have been completely overwritten with zeros before being renamed to its canonical name: the frames of its earlier life would not replay (their CRC covers another file number), but they are not padding either, and a WAL that is not the last of the chain and ends in bytes that are not zeros is a broken tail in the middle of the chain (REC-10a). The implementation does this with a separate file (`WAL.spare`, a non-canonical name that recovery ignores and deletes), which is only renamed when it is complete and durable.

## 7. SST (`NNNNNN.sst`)

### 7.1 Layout

```text
[0, 96)              cabecera común (KRNO_SST, file_number, block_size)
[96, D)              bloques de datos, contiguos (ninguno si la tabla solo tiene rangos)
[rdel_off, +len)     bloque de rangos borrados (solo si range_fragments > 0)
[filter_off, +len)   bloque de filtro
[props_off, +len)    bloque de propiedades
[index_off, +len)    bloque de índice
[len − 80, len)      pie (80 bytes)
```

`D` = `rdel_off` if there is a range block; otherwise, `filter_off`.

### 7.2 Block encapsulation (all types)

```text
payload ‖ slot[40] ‖ crc u32       crc = crc(file_number ‖ block_offset; payload ‖ slot)
```

The block length stored by the index and the footer is `payload_len + 44`.

### 7.3 Data block

```text
entry*  := key_len varint ‖ seq varint ‖ kind u8 ‖ [value_len varint, solo PUT] ‖ key ‖ value
offsets := u32 × count        offsets[0] = 0; estrictamente crecientes; cada uno = inicio de una entrada
count   := u32 ≥ 1
```

- `kind`: 1 = PUT, 2 = DELETE (point tombstone). Another value ⇒ `Corruption`.
- `seq` ∈ [1, 2^63−1].
- **SST-I1.** An SST contains **at most one version per user key**: the keys are strictly increasing within the block and across the file. (Multi-version SSTs would come with an `incompat` bit.)
- The entries cover exactly `[0, start of the offsets)`; no byte is left over.

### 7.4 Range tombstone block

```text
count varint ≥ 1 ‖ fragment*      fragment := bytes(start) ‖ bytes(end) ‖ seq varint
```

- **SST-F1.** Fragments ordered by strictly increasing `start`, `start < end`, not overlapping (`end_i ≤ start_{i+1}`), `seq` ∈ [`smallest_seq`, `largest_seq`].
- **SST-F2 (writer).** Each fragment carries the **largest** sequence of the range tombstones that cover it (correct because a snapshot never sees an SST with sequences greater than its own; see SEM-5). Two adjacent fragments (`end_i = start_{i+1}`) with the same sequence are merged. A point of the same SST covered by a fragment with a greater sequence is not written (the flush or the compaction discards it).

### 7.5 Filter block

```text
filter_kind u8 = 1 ‖ k u8 (1..=30) ‖ reserved u16 = 0 ‖ nbits u32 ‖ bits[nbits/8]
```

- `nbits` ≥ 64, multiple of 8; the payload measures exactly `8 + nbits/8`.
- It contains the user keys of **all the point entries** (PUT and DELETE); ranges are not inserted (a filter cannot discard a range).
- Hash function and probes frozen in §12.

### 7.6 Properties block

TLV (§1.3) with **strictly increasing** tags. Tags 1–12 are mandatory. Unknown tag < 1024 ⇒ `Corruption`; ≥ 1024 ⇒ ignored.

| Tag | Field | Type | Meaning |
|---|---|---|---|
| 1 | `point_entries` | varint | point entries (PUT + DELETE) |
| 2 | `point_deletes` | varint | DELETE entries |
| 3 | `range_fragments` | varint | fragments of the range block |
| 4 | `smallest_seq` | varint | minimum sequence of points and fragments |
| 5 | `largest_seq` | varint | maximum sequence of points and fragments |
| 6 | `data_blocks` | varint | data blocks |
| 7 | `raw_key_bytes` | varint | sum of the lengths of point keys |
| 8 | `raw_value_bytes` | varint | sum of the lengths of values |
| 9 | `smallest_key` | raw bytes | `min(first point key, first start)` |
| 10 | `largest_key` | raw bytes | see tag 11 |
| 11 | `largest_exclusive` | u8 | 1 if the last fragment `end` is greater than the last point key (or there are no points): `largest_key` = that `end` and it is **exclusive**; otherwise 0 and `largest_key` = last point key |
| 12 | `creation_reason` | u8 | 1 flush, 2 compaction, 3 recovery, 4 targeted compaction |

### 7.7 Index block

```text
count varint (= data_blocks) ‖ ( bytes(last_key) ‖ offset varint ‖ len varint ) × count
```

`count = 0` if and only if `point_entries = 0`.

### 7.8 Footer (80 bytes, at `len − 80`)

| Offset | Field | Offset | Field |
|---|---|---|---|
| 0 | `index_off` u64 | 8 | `index_len` u64 |
| 16 | `props_off` u64 | 24 | `props_len` u64 |
| 32 | `filter_off` u64 | 40 | `filter_len` u64 |
| 48 | `rdel_off` u64 | 56 | `rdel_len` u64 (both 0 if there is no range block) |
| 64 | `magic` = `KRNO_SST` | 72 | `reserved` u32 = 0 |
| 76 | `footer_crc` = `crc(file_number; footer[0..76])` | | |

### 7.9 Validation

**When opening the table** (all the sums with overflow checking):

- **SST-O1.** Valid header (HDR-1..10, SST type); `len` = `size` of the `FileMeta`; `len` ≥ 96 + 80.
- **SST-O2.** Footer: CRC, `magic`, `reserved`.
- **SST-O3.** Contiguous layout: if there are ranges, `rdel_off + rdel_len = filter_off`; `filter_off + filter_len = props_off`; `props_off + props_len = index_off`; `index_off + index_len = len − 80`; `D` as in §7.1 and `D ≥ 96`. Without a range block, `rdel_off` and `rdel_len` are 0; if only one of the two is 0, `Corruption`.
- **SST-O4.** Each meta block: length ≥ 44, ≤ limit, CRC, null slot (AEAD-1), exact parsing.
- **SST-O5.** Index: the entries cover exactly `[96, D)` in order, each `len` ≥ 55 (44 of encapsulation + 11 of the minimum payload), `last_key` strictly increasing, `count = data_blocks`.
- **SST-O6.** Properties: tags 1–12 present and valid (`largest_exclusive` ∈ {0, 1}, `creation_reason` ∈ 1..=4); `point_entries + range_fragments > 0`; `point_deletes ≤ point_entries`; `1 ≤ smallest_seq ≤ largest_seq ≤ last_seq` of the MANIFEST; `smallest_key ≤ largest_key` (`<` if `largest_exclusive = 1`); all its fields equal to those of the `FileMeta` (§8.4).
- **SST-O7.** Filter (§7.5) and ranges (SST-F1) well formed; as many fragments as `range_fragments`; each fragment satisfies `smallest_key ≤ start` and `end ≤ largest_key` (with `largest_exclusive = 0` the last `end` does not exceed the last point key, so the condition is the same in both cases).

**On each read of a data block:**

- **SST-R1.** CRC, null slot, structure (§7.3), strictly increasing keys.
- **SST-R2.** Last key of the block = `last_key` of the index; first key > `last_key` of the previous block (block 0: ≥ `smallest_key`).
- **SST-R3.** Every `seq` ∈ [`smallest_seq`, `largest_seq`].

**Only in `verify()`** (full read):

- **SST-V1.** The sum of entries of all the blocks = `point_entries`; DELETE = `point_deletes`; byte sums = tags 7 and 8.
- **SST-V2.** `smallest_key` and `largest_key` match the real first and last ends.
- **SST-V3.** Every point key is in the filter (an incomplete filter would hide keys without error).
- **SST-V4.** No point is covered by a fragment of the same table with a greater sequence (SST-F2).

### 7.10 Writer rules (deterministic, not validated by the reader)

- After adding each entry, the data block is closed if its payload (bytes of the entries + 4 × `count` + 4) reaches `block_size` (4096 in v1); an entry larger than that produces a block with a single entry.
- The filter uses 10 bits per key: `nbits = max(n × 10, 64)` rounded up to the next multiple of 8, `k = 7`.
- With the same entries, the same file number and the same `db_id`, the output is identical byte for byte (a requirement of the vectors, §13).

## 8. MANIFEST

### 8.1 Layout

```text
[0, 96)          cabecera común (KRNO_MAN, file_number = generation, first_edit_seq)
[96, ...)        registro*   registro 0 = SNAPSHOT; los demás se anexan
```

### 8.2 Record

| Offset | Size | Field | Rules |
|---|---|---|---|
| 0 | 4 | `payload_len` u32 | 1..=256 MiB |
| 4 | 4 | `crc` u32 | `crc(generation; bytes[0..4] ‖ bytes[8..24] ‖ payload ‖ slot)` |
| 8 | 8 | `edit_seq` u64 | record 0: `first_edit_seq`; +1 per record (continues across generations); 1..=2^63−1 (§1.4) |
| 16 | 1 | `kind` u8 | 1 `SNAPSHOT`, 2 `SESSION_OPEN`, 3 `FLUSH`, 4 `COMPACTION`; 5 reserved (`MIGRATION`, Phase 4, will arrive with an `incompat` bit); any other ⇒ `Corruption` |
| 17 | 1 | `flags` u8 | 0 |
| 18 | 6 | `reserved` | 0 |
| 24 | `payload_len` | `payload` | TLV (§8.3) |
| … | 40 | `slot` | §5 |

Minimum size of a record: 24 + 1 + 40 = 65 bytes.

### 8.3 Fields (TLV)

Tags **non-decreasing**; only 10 and 11 may repeat. Unknown tag < 1024 ⇒ `Corruption`; ≥ 1024 ⇒ ignored.

| Tag | Field | Value |
|---|---|---|
| 1 | `next_file` | varint: next file number not yet used |
| 2 | `last_seq` | varint: last sequence contained in the SSTs |
| 3 | `log_number` | varint: **exact** number of the oldest live WAL (or `next_file` if there is none) |
| 4 | `num_levels` | u8: v1 accepts 7; another value in 2..=16 ⇒ `Incompatible`; outside ⇒ `Corruption` |
| 5 | `flags` | varint: bit 0 = `CLEAN`; other bits ⇒ `Corruption` |
| 6 | `reason` | u8: 1 background, 2 targeted (`compact_range`), 3 close, 4 trivial move |
| 7 | `prev_generation` | varint: generation of the MANIFEST that was replaced (0 at creation) |
| 10 | `add_file` | `FileMeta` (§8.4) |
| 11 | `delete_file` | `level u8 ‖ number varint` |

Fields per record type:

| Type | Mandatory | Optional | Anything else |
|---|---|---|---|
| `SNAPSHOT` | 1, 2, 3, 4, 5, 7 | 10* (by increasing levels; L0 from newest to oldest; Ln by `smallest`) | `Corruption` |
| `SESSION_OPEN` | 1, 2, 3 | 10* (level 0 only: outputs of the recovery flush, from newest to oldest) | `Corruption` |
| `FLUSH` | 1, 2, 3 | 6, 10* (level 0 only) | `Corruption` |
| `COMPACTION` | 6 | 1, 10* (levels ≥ 1), 11* | `Corruption` |

### 8.4 `FileMeta`

```text
level u8 ‖ number varint ‖ size varint ‖ point_entries varint ‖ range_fragments varint ‖
smallest_seq varint ‖ largest_seq varint ‖ flags u8 (bit 0 = largest_exclusive; otros ⇒ Corruption) ‖
bytes(smallest) ‖ bytes(largest)
```

All the fields must match the properties of the SST (SST-O6).

### 8.5 Applying records

- `SNAPSHOT`: replaces the complete state. It is only valid as record 0 of a file. With `CLEAN`, it requires `log_number = next_file`.
- `SESSION_OPEN`: sets 1, 2, 3; prepends the files to L0 in the given order; the state stops being clean.
- `FLUSH`: sets 1, 2, 3; prepends the files to L0 (0 or more; a flush of a memtable that only received commits without effect produces no files, but does raise `last_seq`).
- `COMPACTION`: sets 1 if present; deletes each `delete_file` (it must exist in that level) and then adds each `add_file` to its level, in the position that corresponds to it by `smallest` (level ≥ 1; level 0 ⇒ `Corruption` in v1). A trivial move is one deletion plus one addition of the same file with `reason = 4`.
- **MAN-A1.** `next_file`, `last_seq` and `log_number` never decrease from one record to the next.

### 8.6 State validation (after applying each record)

- **MAN-S1.** Unique file numbers ≥ 1; all < `next_file` ≤ 2^48−1; `1 ≤ log_number ≤ next_file`; `last_seq ≤ 2^63−1` (format limit of §1.4).
- **MAN-S2.** Each file: `point_entries + range_fragments > 0`, `smallest ≤ largest` (`<` if `largest_exclusive`), `1 ≤ smallest_seq ≤ largest_seq ≤ last_seq`.
- **MAN-S3.** Levels ≥ 1 ordered and disjoint: for consecutive files `f`, `g`, `f` ends before `g.smallest` (if `f` is exclusive, `f.largest ≤ g.smallest`; otherwise, `f.largest < g.smallest`).
- **MAN-S4.** L0: for two files `i` before `j` whose key ranges overlap (with the same exclusivity rule), `smallest_seq(i) > largest_seq(j)`. L0 files that do not overlap (e.g. those of one split flush) may have interleaved sequence ranges.
- **MAN-S5.** `num_levels = 7`; every `level` of `add_file` and `delete_file` < 7; ≤ 2^20 files per level. `num_levels` and the levels are checked when the fields are decoded (§13.1).

A reader does not need to revalidate the whole state after each record: record 0 is validated in full and each following record only in what changes, with the same result, because the previous state was valid and MAN-A1 prevents `next_file` and `last_seq` from decreasing. It is enough to apply: MAN-S1 to the scalars and to the numbers added (against the set of numbers in the state); MAN-S2 to the files added; MAN-S3 to the neighbours of each file added (deleting a file does not disorder a level: "ends before the next one starts" is transitive through the deleted file, which satisfied MAN-S2); MAN-S4 to L0 if files were prepended to it (deleting does not break it: it is a rule over pairs); MAN-S5 to the levels that grow. Checked in that order, the reported rule is the same. Thus replay costs what the records change, and not records × files.

### 8.7 MANIFEST replay (reader)

- **MAN-R1.** Valid header (HDR), `generation` ≥ 1, and record 0 = a valid `SNAPSHOT` with `edit_seq = first_edit_seq` and `prev_generation = generation − 1`. If not (including an empty, short or truncated file within record 0) ⇒ `Corruption` (I-09). Record 0 was written before the rename, so it can never be broken by a crash.
- **MAN-R2.** Records are read until the first invalid one, at `P`. One with a valid CRC but wrong `edit_seq` or `kind`, a non-null slot, or fields that violate §8.3–§8.6 ⇒ `Corruption`.
- **MAN-R3.** If `P` < the length of the file and from `P` everything is zeros ⇒ clean end. Otherwise, candidate records are searched at each offset > `P` with `edit_seq ∈ [expected, expected + ⌊(len − P)/65⌋ + 1]`, length in range and valid CRC: if any exists ⇒ `Corruption` (each record is synced before writing the next one, W-3); if not ⇒ **broken tail** at `P`, accepted.
- **MAN-R4.** The state is **clean** if and only if the last valid record is a `SNAPSHOT` with `CLEAN`.

### 8.8 MANIFEST writer rules

- **W-3.** A record is written with a single `write_at` and synced (`sync_data`) before the next one is written, before deleting anything that it makes obsolete, and before publishing the new version.
- **W-4.** An SST is synced (`sync_data`) and so is its directory entry (`sync_dir`) before a record references it.
- **W-7.** Nothing is ever appended after an invalid tail (neither in the MANIFEST nor in a WAL): a checkpoint is written or a new WAL is created.

### 8.9 Checkpoint

- **W-10.** Delete an old `MANIFEST.tmp`; write `MANIFEST.tmp` (header with `generation + 1`, `first_edit_seq` = next `edit_seq`, and a single `SNAPSHOT`) → `sync_data` → `rename` to `MANIFEST` → `sync_dir`.
- Triggers: `close()` (with `CLEAN`); opening with a broken tail (W-7); the appended bytes exceed `max(4 MiB, 4 × size of record 0)`; `compact_range` (so that the keys of the range leave the edit history).

## 9. Recovery: decision table

Recovery is part of the format: these rules are frozen with it. First the directory is **classified** and everything necessary is validated without writing anything; then, only in read-write, the session start (§9.4) runs.

### 9.1 Without MANIFEST

| # | Situation | Result |
|---|---|---|
| REC-1 | Directory non-existent, empty, or with only `LOCK` and/or `MANIFEST.tmp` | read-write with `create_if_missing`: create (DIR-3); otherwise `InvalidArgument("no database")` |
| REC-2 | Canonical `.wal` or `.sst` files exist | `Corruption` |
| REC-3 | Other files exist | `InvalidArgument("not a Kerno database")`, touching nothing |

### 9.2 With MANIFEST

| # | Situation | Result |
|---|---|---|
| REC-4 | Invalid header or replay (HDR, MAN-R); M0 *magic* | `Corruption`; `Incompatible` |
| REC-5 | Referenced SST missing, of a different size, or with a different `db_id`, number or properties | `Corruption` |
| REC-6 | **Clean** and an SST exists with a number ≥ `next_file` | `Corruption` (evidence of a lost `SESSION_OPEN`: W-8) |
| REC-7 | **Clean** and a WAL exists with a number ≥ `next_file`: with ≥ 1 valid frame ⇒ `Corruption`; without frames (empty or with a broken header) ⇒ orphan | |
| REC-8 | **Clean**: any canonical file not referenced with a number < `next_file` | orphan |
| REC-9 | **Dirty** and the WAL `log_number` does not exist | `Corruption("required WAL missing")` (W-1 and W-5 guarantee that it exists; it detects a damaged last `FLUSH` or `SESSION_OPEN` whose WAL has already been deleted) |
| REC-10 | **Dirty**: live WALs = the canonical ones ≥ `log_number`, by number | chain rule, §9.3 |
| REC-11 | **Dirty**: SSTs not referenced (any number) and WALs < `log_number` | orphans |
| REC-12 | `MANIFEST.tmp` | ignored; deleted in read-write |
| REC-13 | Unknown files | ignored; never deleted |

### 9.3 Chain of live WALs (REC-10)

Let `W_1 < … < W_n` be the live WALs and `k` the index of the last one that has at least one valid frame (`k = 0` if none).

- **REC-10a.** `W_1, …, W_{k−1}`: valid header and no broken tail (they may end in zero padding); otherwise ⇒ `Corruption`.
- **REC-10b.** `W_k` may end in a broken tail (WAL-R5).
- **REC-10c.** `W_{k+1}, …, W_n` have no frames; each has a broken header (WAL-R6) or a valid header with `base_seq` = the sequence expected after `W_k`; otherwise ⇒ `Corruption`.
- **REC-10d.** Each valid header meets WAL-R1 (continuity of `base_seq`).

REC-10c is what makes recovery **re-entrant** (I-11): the session start creates the new WAL *before* its record in the MANIFEST (§9.4), so a crash between both steps after a dirty close with a broken tail leaves a broken `W_k` followed by an empty WAL, and that must remain recoverable. A targeted test of chained crashes (`chained_crash_during_session_start_after_torn_wal`) checks it.

### 9.4 Session start (read-write)

- **S-1.** Full classification and validation (§9.1–§9.3), without writing.
- **S-2.** If the state is dirty and the replay produced commits: write the replayed memtables as L0 SSTs, splitting each time the memtable reaches `write_buffer_bytes` (bounded recovery memory); `sync_data` of each one; `sync_dir`.
- **S-3.** Reserve the number `X` and create the WAL `X` (W-1) with `base_seq = last_seq + 1`.
- **S-4.** If the MANIFEST ended in a broken tail or exceeds the checkpoint trigger: checkpoint (W-10) with a `SNAPSHOT` without `CLEAN` and `log_number = X`. Otherwise: append `SESSION_OPEN{next_file, last_seq, log_number = X, add_file of S-2}` and `sync_data`.
- **S-5.** Publish the state; delete orphans (REC-7, REC-8, REC-11) and an old `MANIFEST.tmp`; `sync_dir` if anything was deleted.
- **S-6.** Start the background threads.
- **W-8.** No frame is written to the WAL `X` before the record of S-4 is durable.

Cost of a clean reopen: `sync_dir` (S-3) + `sync_data` (S-4) = 2 synchronizations (M0: 3).

**Implementation status (WP07, provisional until WP08).** The engine validates everything in S-1 (HDR-1..10 in each file it reads, WAL-R1..R6, REC-10, SST-O1..O7) before writing anything, but it does not yet append records: each change in the shape of the LSM writes a new generation of the MANIFEST with a single `SNAPSHOT` (§8.9), and the session start keeps the M0 order (recovery SST, new MANIFEST with the `log_number` of the next WAL, deletion of the obsolete files and, at the end, creation of the WAL). With that order the `base_seq` of the new WAL is the `last_seq` of an already durable MANIFEST, and a crash between both steps leaves a MANIFEST without a live WAL, which is accepted: the rule REC-9 (required WAL absent) and those of the clean state (REC-6..REC-8) do not apply until WP08. `close()` writes the `CLEAN` `SNAPSHOT` (with `log_number = next_file`) after the last compaction (W-9), but nothing requires it yet. An unknown `ro_compat` bit (HDR-7) gives `Incompatible` instead of opening read-only, and a WAL with ranges or an SST with fragments give `Incompatible` instead of ignoring the tombstones, until read-only opening (WP08) and ranges (WP10) exist.

### 9.5 Read-only, `verify()` and `inspect()`

- **RO-1.** They take the exclusive `LOCK` (`Locked` if the database is open); they may create `LOCK`; they do not do `create_dir_all`, `sync_dir`, deletions, checkpoints or flush.
- **RO-2.** They apply §9.1–§9.3 unchanged; the live WALs are replayed in memory (the memory is proportional to the live WALs, bounded by the writer to `(max_immutable + 1) × write_buffer` plus a group). `verify()` materializes nothing: it validates as a stream.
- **RO-3.** Orphans, `MANIFEST.tmp` and unknown files are reported, never deleted.
- **RO-4 (races with orphan snapshots).** A snapshot that survived an earlier handle may delete obsolete files while another opening inspects them. As a file only becomes obsolete after a durable MANIFEST stops referencing it, and numbers are never reused, the rule is: `NotFound` when opening an **unreferenced** file ⇒ "orphan that disappeared" (informative); `NotFound` of a **referenced** one ⇒ `Corruption`.

**Implementation status (WP09).** `verify()` and `inspect()` exist as library functions of `kerno-storage` (the CLI arrives in Phase 2). `verify()` applies §9.1–§9.3 with the same classification function as the openings, dry-replays each live WAL, opens each referenced SST with SST-O1..O7 and reads all its blocks (SST-R1..R3, SST-V1..V4) without going through the cache and without whole-file buffers. Damage is an `Issue` with the rule identifier; `Err` is kept for `Io`, `Locked`, `Incompatible` and `InvalidArgument` (a directory that is not a database). The classification REC-5..REC-10 reports only the first violated rule, as the opening does; the rest of the checks continue. An orphan that disappears during the check is reported separately (RO-4); a referenced SST that disappears is a violation of REC-5. `inspect()` reads only headers: a damaged header is listed with the violated rule, and an incompatible version or bit is `Incompatible`.

## 10. Writer invariants (summary)

| Id | Rule |
|---|---|
| W-1 | WAL creation: `CreateNew`, header, `sync_data`, `sync_dir`; the header is durable before the first frame (§6.5) |
| W-2 | `Buffered`: `sync_data` of the current WAL before creating the next one |
| W-3 | MANIFEST record synced before the next one, before deleting what it makes obsolete, and before publishing |
| W-4 | SST synced (`sync_data` + `sync_dir`) before being referenced |
| W-5 | A WAL is deleted only when a durable record moves `log_number` past it, or after a durable `CLEAN` checkpoint |
| W-6 | An SST is deleted only when a durable record removes it **and** no version or snapshot retains it; the deletion is done by a dedicated thread with retries (W-13) |
| W-7 | Nothing is ever appended after an invalid tail |
| W-8 | No frame in the first WAL of a session before its `SESSION_OPEN` (or checkpoint) is durable |
| W-9 | Order of `close()`: (1) stop the background work and drain the commit queue; (2) if the active memtable received commits, rotate (W-1, W-2); (3) flush the immutables from the oldest to the newest, one `FLUSH` each; (4) mandatory compaction until L0 is below its trigger, then with budget; (5) `CLEAN` checkpoint with `log_number = next_file`; (6) delete all the WALs and `sync_dir` |
| W-10 | Checkpoint protocol and triggers (§8.9) |
| W-11 | `synced_len` never exceeds the synced prefix; a failed `fsync` poisons (§6.5) |
| W-12 | Publication: in `Sync`, a sequence is published only after the `fsync` of the frame that contains it; `s` is never published before all the `< s` have been applied (I-05, I-16) |
| W-13 | Obsolete files are deleted in a dedicated thread; a deletion failure is retried and counted (`obsolete_bytes_pending`, `delete_failures`); a referenced file is never deleted |

## 11. Frozen semantics

- **SEM-1.** Each non-empty commit receives the next sequence (u64, from 1, maximum 2^63−1); the sequences are consecutive across frames and across WALs.
- **SEM-2.** A batch is applied atomically: all its operations have the same sequence.
- **SEM-3.** Order within a batch: the canonical form (WAL-C1) applies the ranges and then the points; consequently, **a point and a range with the same sequence: the point wins**.
- **SEM-4 (visibility).** A point entry `p@s` of the key `k` is visible in the snapshot `S` if and only if `s ≤ S`, it is the newest version of `k` with sequence ≤ `S`, and **there is no** fragment `[a, b)@u` with `a ≤ k < b` and `s < u ≤ S`. A visible point tombstone means "absent".
- **SEM-5.** Every SST of the version that fixes a snapshot `S` contains only sequences ≤ `S`; that is why one sequence per fragment in the SSTs suffices (SST-F2), while the memtable keeps all of them.
- **SEM-6 (order of sources).** For overlapping keys: active memtable > immutables (from newest to oldest) > L0 (MAN-S4) > L1 > … > L6; the deeper levels contain strictly older data. The file bounds include the extension of their fragments.
- **SEM-7.** A point tombstone or a fragment is only discarded in compaction when no file of a level deeper than the output overlaps with it.

## 12. Frozen constants

- **Bloom filter.** `h = fmix64(fnv1a64(key))`, with FNV-1a 64 (base `0xcbf29ce484222325`, prime `0x100000001b3`, xor and then multiplication per byte) and `fmix64(h)`: `h ^= h >> 33; h *= 0xff51afd7ed558ccd; h ^= h >> 33; h *= 0xc4ceb9fe1a85ec53; h ^= h >> 33` (multiplications modulo 2^64). Probe `j` (0 ≤ j < k): `a_0 = h & 0xffffffff`, `a_{j+1} = a_j + ((h >> 32) | 1)` (modulo 2^64), bit `a_j mod nbits`. Bit `i` is in byte `i / 8` with mask `1 << (i % 8)`. It is the function of `spike-lsm/src/bloom.rs`.
- **Varints:** VAR-1..3. **Levels:** 7. **Block size written:** 4096. **Header:** 96 bytes. **Block encapsulation:** 44 bytes. **SST footer:** 80 bytes. **Frame header:** 32 bytes. **Record header:** 24 bytes.

## 13. Test vectors (ADR-0003 §7)

### 13.1 Level 1: structures (WP06)

`crates/kerno-storage/tests/vectors/v1/structs/<name>.bin` plus a Rust table that associates each name with the entry it encodes. Both directions are checked: `encode(entry) == bytes` and `decode(bytes) == entry`.

### 13.2 Level 2: directories (WP11, extended later)

`crates/kerno-storage/tests/vectors/v1/dirs/<case>/` with the raw files and `EXPECTED` (text: `seq=N`, `mode=rw|ro|reject:<Class>`, `clean=0|1` and one line `hex(key)\thex(value)` per live key). A rejected case carries `seq=0`, `clean=0` and no key. `LOCK` is not part of a vector.

- **Deterministic generation:** `#[ignore] regenerate_v1_vectors` with `Background::Inline`, a fixed `db_id` `00..0f`, a close budget in bytes only, `Rng(2026)`, and crashes chosen by an operation filter in `SimVfs` for the dirty cases. The compaction levers are fixed at the values of M0 (`CompactionConfig::m0`), so that changing the engine's default values does not move the bytes of a vector. A `SimVfs` crash occurs just *before* the chosen operation and randomly keeps part of the pending writes, so the cases with a broken tail (`dirty-wal-torn-tail`, `dirty-torn-newest-header`, `dirty-manifest-torn-tail`) are generated with the first seed of `0..64` whose result has the wanted shape (checked with `scan_wal` and `replay_manifest`); the search is deterministic.
- **Positive:** `empty-clean`, `basic-clean` (L0 + L1 + L2), `range-delete-clean`, `tombstone-only-sst`, `flush-split-l0`, `dirty-wal-torn-tail`, `dirty-torn-newest-header`, `dirty-chained-session-start` (REC-10c), `dirty-manifest-torn-tail`, `checkpoint-plus-edits`, `large-value-1mib`. Added with group commit: `dirty-group-frame` (a frame of three commits, formed without depending on the clock: a `HookVfs` holds the leader while the other writers queue up one by one), `dirty-buffered-synced-len` (`Buffered` with a `sync()` in between: some frames carry `synced_len = 96` and others more), `dirty-wal-one-frame` (a WAL with a single frame, of `synced_len = 96`).
- **Negative:** `future-version-{man,wal,sst}`, `unknown-incompat-{man,wal,sst}`, `aead-bit-set` (all `Incompatible`, directory intact); `unknown-ro-compat` (opens read-only); `unknown-compat` (opens read-write; the bit disappears after the next checkpoint); `m0-spike-lsm` (`Incompatible`), `m0-spike-btree` and `reference-log` (`InvalidArgument`); `foreign-db-id-sst`, `renamed-sst`, `missing-log-wal`, `bytes-after-clean`, `wal-mid-damage-synced`, `wal-one-frame-broken-header` (`Corruption`: broken header under a single valid frame, WAL-R6). The header ones are derived from a positive with `format::patch_header`, which recomputes the header CRC to violate a single rule. Those of M0 and the reference come from `spike-lsm`, `spike-btree` (development dependencies, only to generate them) and `LogEngine`. `draft-v1` (`Incompatible`: all the files with bit 63 of `incompat`, the one the draft wrote).
- **Implementation status.** All the cases above are generated, `draft-v1` included (added with the freeze). `range-delete-clean`, which WP11 left pending because the engine did not yet write range tombstones, was added in WP14 (WP10b already writes them): adding a vector does not change the bytes of the existing ones.
- **Loading:** each vector is copied to a `SimVfs` (write, `sync_data`, `sync_dir`) and to a temporary directory with `StdVfs`; it is opened read-only and read-write, the sequence and the content are compared, `verify()` must come out clean, and the negative ones must leave the directory identical byte for byte (except `LOCK`). Tests (`tests/dir_vectors.rs`): `dir_vectors_open_exact_sim`, `dir_vectors_open_exact_std`, `dir_vectors_open_read_only`, `dir_vectors_verify_clean`, `dir_vectors_negative_untouched`, `dir_vectors_are_reproducible`, `dir_vectors_exhaustive_bit_flips`, `dir_vectors_truncate_every_offset` and `regenerate_v1_vectors` (`#[ignore]`).

### 13.3 Regeneration guard

`dir_vectors_are_reproducible` and `struct_vectors_encode_exact` regenerate in memory and compare byte for byte with what is versioned. Any change of a v1 byte fails in CI. Adding vectors is always allowed; changing existing bytes only through the process of §15.

### 13.4 Exhaustive damage

On each clean vector of level 2 (the positive ones with `mode=rw` and `clean=1`): invert each bit of each byte and truncate each file at each offset. Each result must be an error of the damage class (`Corruption`, `Io`) or the exact content; for the clean vectors **zero harmless results** are required, which demonstrates that no byte remains uncovered. Each test opens read-only and reads all the content; any other result (another error class, another sequence, other data) also fails the test.

A file of more than 64 KiB (only the SST of `large-value-1mib`) is not walked entirely, because each bit would cost reading and verifying a 1 MiB block: all the bits and all the offsets of its first 512 bytes and of its last 4096 (header, range block, filter, properties, index, footer and the end of the data block) are walked, and one of every 1021 bytes of the rest. The other vectors are walked whole.

## 14. Compatibility

| Input | Result of a v1 reader |
|---|---|
| v1 files without unknown bits | they open |
| `format_version` > 1, unknown `incompat` bit, `AEAD`, `num_levels` ≠ 7 in 2..=16 | `Incompatible`, without modifying anything |
| Unknown `ro_compat` bit | read-only |
| M0 prototype `spike-lsm` (`KRNOMAN1`, `KRNOSST1`) | `Incompatible("M0 prototype format")` |
| M0 prototype `spike-btree`, reference engine `LogEngine`, any foreign directory | `InvalidArgument("not a Kerno database")` |
| Draft before the freeze (`DRAFT` bit), once v1 is frozen | `Incompatible("pre-freeze draft format")` |

v1 migrates nothing: there is no earlier supported version. The migration framework (ADR-0003 §5) arrives with v2 (Phases 4–6); v1 reserves record type 5 and the `incompat` bits for it. <a id="15-proceso-de-cambios-del-borrador-y-congelación"></a>

## 15. Process for changes to the draft and the freeze

- Until the freeze (2026-10-31), changing a byte of the format required, **in the same PR**: an entry in the "Draft history" table below, the update of this document, the regeneration of the affected vectors with the corresponding note in ADR-0013, and the rerun of `spec_decoder_agrees` and of the corruption suites. If the change touches checksums, the AEAD slot, the header or data deletion, the revision of the threat model is marked as pending.
- The freeze (WP14) required ADR-0013 accepted by the owner and the threat model reviewed (R-07); it retired the `DRAFT` bit, regenerated all the vectors and fixed the guard. From it on, any change of bytes requires raising `format_version` or a new feature bit, plus vectors and an ADR.

## 16. Differences from the M0 prototype (`spike-lsm`)

| Aspect | M0 | v1 |
|---|---|---|
| Identification | WAL without header; SST with *magic* only in the footer; MANIFEST with *magic* and version inside the body | common 96-byte header with version, bits, `db_id` and file number |
| WAL record | 16-byte header, one commit per record, bit 31 `SYNCED` | 32-byte frame per **group** of commits, `synced_len` (WAL-R5), canonical batch, `DELETE_RANGE` |
| WAL: replay | whole file in memory | as a stream, 1 MiB per read |
| SST | 8-byte block trailer, 52-byte footer, no properties | 44-byte encapsulation with AEAD slot, CRC with context, TLV properties, range block, 80-byte footer |
| MANIFEST | full snapshot on each edit (2 synchronizations) | edit log (1 synchronization), checkpoints by rename, `CLEAN` mark |
| `log_number` | `wal_number + 1` of the last flush (may not be a WAL) | exact number of the oldest live WAL; a required WAL that is absent is `Corruption` |
| L0 | order not verifiable | sequence ranges in `FileMeta`; MAN-S4 |
| Clean reopen | rewrites the MANIFEST and creates a WAL (3 synchronizations) | appends `SESSION_OPEN` (2 synchronizations) |
| Limits | none in the format; batch ≤ 2 GiB | separate format and API limits (§1.4) |
