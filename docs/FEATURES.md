# Kerno feature inventory

Master list of Kerno's capabilities, each with a status audited against the code, the tests and the
decision records. It is not a plan: a feature appears as implemented only when code exists and a test
or a measurement in the repository exercises it. The roadmap is in [ROADMAP.md](../ROADMAP.md).

| Field | Value |
|---|---|
| Audit date | 2026-11-19 |
| Scope | The workspace at the commit this file was written on (`locks/task-2644`, based on `7a58f88`) |
| Commands run | `cargo test -p kerno --release` (26 passed), `cargo test -p kerno-mcp --release --test e2e` (7 passed), `cargo test -p kerno-cli --release --test cli` (30 passed) |
| Not re-run | The rest of the workspace suites, the benchmarks and the fuzzers. Those statuses rest on reading the code and the test files, and on the closure documents the repository already holds |

## Legend

| Status | Meaning |
|---|---|
| IMPLEMENTED | Code exists and tests or measurements in the repository prove it. Gaps, if any, are named in the row |
| PARTIAL | Code exists, but a stated part of the feature is missing. The gap is named in the row |
| IN_PROGRESS | Work has started and is not finished. No row needs this status today |
| EXPERIMENTAL | Code exists behind a flag, outside the default path, or only in an experiment directory |
| PROPOSED | Not in the code. A design or an idea only |
| DEFERRED | Decided to be out of scope for the first stable release. The reason is in the row |
| REJECTED | A decision closed it. The reason is in the row |

A type or struct alone never earns IMPLEMENTED. Where the evidence was unclear, the row is PARTIAL.

### PARTIAL and PROPOSED items that block 1.0 (ROADMAP.md)

These are the unticked items in ROADMAP.md, mapped to the rows that carry them. The ROADMAP orders
Phase A and Phase C before Phase D, so every item below is needed before 1.0 by the roadmap's own order.

**Phase A: usable from the languages AI is built in**

- Python bindings published on PyPI: row INT-05 (PARTIAL).
- Node/TypeScript bindings published on npm: row INT-06 (PARTIAL).
- The `kerno` facade crate published on crates.io: row ENG-02 (PARTIAL).
- Prebuilt binaries of `kerno` and `kerno-mcp` for Linux, macOS and Windows: row ENG-03 (PARTIAL).

**Phase C: a real general-purpose embedded database**

- Closed performance gaps U2 and U6, and a published, reproducible SQLite benchmark: rows OPS-06, OPS-08 and OPS-10 (PARTIAL). U2 is closed on tmpfs. U6 is not met on disk; its medians (§3.8) are pending ([docs/testing/phase-c-performance.md](testing/phase-c-performance.md)).
- Long fuzzing runs (about 30 h, on an idle machine or in Docker on dedicated cores): row OPS-13 (PARTIAL). The script and the Docker setup exist; the run has not been executed.

**Phase D: 1.0 (no engineering row; the owner decides)**

- Real use outside the core team, with feedback addressed. Not met: the only use case is `examples/agent-memory/`, an internal one ([docs/architecture/requirements-1.0.md](architecture/requirements-1.0.md) §3).
- Contributor license text approved. A draft exists in [docs/legal/cla-draft.md](legal/cla-draft.md) and is not in force.

**Ticked in ROADMAP.md but PARTIAL here.** These are not unticked, but a 1.0 reader would take them as done:

- "File format and API compatibility promise" (Phase D, ticked). [docs/compatibility.md](compatibility.md) says "Status: proposed", and the crate version is 1.0.0-alpha.1. Row ENG-07 (PARTIAL).
- "Concurrency across threads and processes" (Phase C, ticked). Only threads of one process share a database. A second process is refused with `Locked`. Row ENG-10 (PARTIAL), and [docs/concurrency.md](concurrency.md) §Processes.
- "Pluggable embedding providers: a local model or a remote API" (Phase B, ticked). The crate ships a deterministic hashing provider (not semantic) and an OpenAI-compatible HTTP adapter. No local semantic model is in the crate. Row IDX-16 (PARTIAL).
- "Memory hygiene ... summarizing old memory" (Phase B, ticked). Importance, dedup and expiry exist (rows REV-17, FUT-08). Summaries live in memory only, with no on-disk format ([docs/architecture/stage8-closure.md](architecture/stage8-closure.md), decision D8): row REV-18 (PARTIAL).
- "Typed schemas" and "user-defined secondary indexes" (Phase C, ticked). The code exists and is tested, but [ADR-0021](adr/0021-typed-schemas-and-secondary-indexes.md) is still "Proposed, pending the owner's acceptance". Rows IDX-02 and DM-05 carry the gap.

### Contradictions between ROADMAP.md and the code

- **Cross-process concurrency.** The ROADMAP's Phase C line says "across threads and processes". The code and [docs/concurrency.md](concurrency.md) say one process at a time owns a directory: the second process gets `Locked`, even read-only ([crates/kerno-storage/tests/process_lock.rs](../crates/kerno-storage/tests/process_lock.rs)). Row ENG-10.
